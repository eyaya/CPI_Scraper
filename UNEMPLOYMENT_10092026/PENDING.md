# Pending countries — resolved routes, layouts still needed

These NSOs are **reachable and their labour publication has been located**, but
no descriptor ships for them yet because the table's structure could not be read
before delivery. Each entry below carries everything needed to add it: the exact
access route, the file, and what is missing.

The routes here are not guesses. Most were recovered from the **CPI and GDP
collectors already in this repo**, which download from these same hosts
successfully every run — the working host, method and flags are copied from
descriptors that are in production. Several sites that a plain fetch reports as
"blocked" (403, an SPA shell, a TLS failure) are reached without trouble by the
pipeline's `requests` + Chrome UA + `verify=False` client, and in two cases by
the `curl_cffi` browser fingerprint. **Do not re-classify these as blocked on
the strength of a browser or a fetch tool failing.**

To add one: download the file, read its headline table, write the layout in
`parsers/<country>_unemployment.py` (or `excel_layouts.py`), add
`sources/<country>.yaml` with
the route below, and run the offline tests.

## B. Genuinely not collectable — and why

Recorded so nobody re-runs the search.

- **Eritrea** — no NSO web presence of any kind. Recommend dropping rather than carrying a permanently-failing descriptor.
- **Sudan** — `cbs.gov.sd` fails at **DNS**; the domain is gone. The Central Bank of Sudan is reachable from Port Sudan but publishes only monetary and trade statistics, so it does not qualify as an NSO-republishing fallback.
- **South Sudan** — NBS is live and serves other PDFs, but `statistics/Labor_Market.php` is a placeholder reading "currently being updated". Poll and wait.
- **Central African Republic** — ICASEES's site and NADA are healthy and the **whole `enquetes-et-etude` tree was enumerated** (11 sub-categories, ~23 documents): nothing on emploi, chômage, main-d'œuvre or secteur informel. ECASEB is a welfare survey and its listed file is 4 KB, so probably a stub. Watch for EHCVM2, whose fieldwork is recent.
- **Congo-Brazzaville** — `ins-congo.cg` is a **JS SPA** with files at `/uploads/<category>/ins_<hash>.pdf`; the CPI descriptor's WordPress Download-Monitor model does not apply to its labour pages. More to the point, Congo announced in **July 2026** that it is only now *preparing* its first labour-market survey, which is the likelier reason the employment page's table is empty. High-value re-check in a year.
- **DR Congo** — there is **no JSON API**: `/api/indicateurs`, `/api/portail`, `/api/statistiques` and `/_next/data` all 404, and the "Excel to normalised JSON" pipeline INS advertises is a build-time step. The upstream workbook is exposed at `https://www.ins.gouv.cd/chiffres/Indicateurs_cles.xlsx`, but the statistical portal carries 15 indicators across inflation, national accounts, poverty, FDI, debt and mining — **no employment category at all**. ECVM 2024's published scope names no labour module. Press figures attributed to ECVM (55.9% "national") read as employment ratios, not unemployment rates, and the article contradicts itself — do not ingest them.
- **São Tomé & Príncipe** — the employment category is **59** (`.../phocadownload/category/59-emprego`), not 55 as the site's own broken link suggests; enumerate from category 49, the parent index. It holds **exactly two PDFs, both 2018-vintage, both covering 2000–2015**. The site's "8.9% (2017)" headline has no linked source document. V RGPH 2024 renders but contains no unemployment rate, no activity rate and no labour tables. Park pending a census labour volume.
- **Mozambique** — the dedicated labour survey (**IFTRAB**) has one round only, **2004/05**, never repeated, and there is no periodic employment release. Labour figures exist only inside the **IOF household-budget survey**, whose Chapter 6 "EMPREGO" is computed on a **5-years-and-over** base with a 12-month reference period — far outside the ILO convention and not comparable. INFOR 2021/22 covers the informal sector, not open unemployment. Flag as **methodologically incompatible**, not merely missing. (Searches collide with INE *Portugal*'s "Estatísticas do Emprego" — a different country.)
- **Djibouti** — INSTAD is a React SPA returning meta tags only. ⚠️ Do not confuse `instad.dj` (Djibouti) with `instad.bj` (**Benin**) — search engines conflate them and Benin's site *is* reachable, which would silently poison a scraper.
- **Libya** — the 2022 LFS PDF is live but **>30 MB**; expect a scanned, image-heavy report needing OCR. ⚠️ `bsc.ly` carries **injected spam content** in its page bodies — extract only `wp-content/uploads` hrefs and never trust page text.

## C. Useful patterns learned while resolving these

- **Always hit a NADA catalog's `/related-materials` page**, never just `/catalog/<id>` — the landing page hides report attachments behind a microdata call-to-action, which is why Burkina, Senegal and Mozambique all looked "microdata only" at first.
- **A fetch tool's failure is not the site's verdict.** `anstat.ci` (403), `www.ons.dz` (TLS chain), `ine.cv` (SPA shell to every path), `www.ansd.sn` and `www.ine.gov.mz` (broken intermediate certs), `knbs.or.ke` (intermittent robots/TLS) are all reached by this repo's production client.
- **Aggregator contamination reaches into NSO sites themselves.** Botswana, Lesotho, Malawi, Gabon, CAR and Congo all link their own "data portal" to `*.opendataforafrica.org` (Knoema). Blocklist the domain in the fetcher; an NSO endorsing an aggregator does not make it NSO data.
- **Beware the summarising extractor.** Fetch tools that convert a PDF and answer through a model will, when a text layer is short, silently substitute plausible figures. It happened on Lesotho, on Gambia's Table 2.1 and on Equatorial Guinea's Tabla 46 — each time producing a well-formed table that was invented. Prompts that force a literal transcription and offer an explicit "NOT IN EXTRACTED TEXT" escape hatch are the only reliable way to tell.
